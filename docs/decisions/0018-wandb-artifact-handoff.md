# Move trained adapters and eval data between machines as verified W&B artifacts, in two phases

## Context and Problem Statement

Training finished on the Windows RTX box; the adapters and eval episodes had to reach the Mac. The two agents (one per machine) coordinate only through git, and the Windows PC exposes no inbound access.

## Decision Drivers

* Nothing should be exposed on the Windows PC (the user's decision: "a W&B artifact ..., NOT scp").
* The transfer must be verifiable (truncated downloads must be detected).
* The user changed the plan on 2026-11-08: ship training outputs immediately and eval data later, since evals would take hours.

## Considered Options

* `scp` from the Mac into the PC (rejected: would need an inbound service on the PC; an `sshd` service was in fact running, which the handoff deliberately does not use).
* Commit adapters to git (rejected: 70 MB each, 1.8 GB total).
* W&B artifact + sha256 manifest committed to git (chosen).

## Decision Outcome

Chosen option: "W&B artifacts with git-tracked manifests", in two phases:

* Phase 1 `wikigame-handoff-training:v0` (56 files, 1.8 GB): every checkpoint's adapter files (no optimizer state) for stage 1b (25..275), stage 2 (25..300) and stage 1 `checkpoint-25`, the final adapters plus `wikigame_config.json`, small logs. Manifest `handoff/MANIFEST-training.txt`.
* Phase 2 `wikigame-handoff-eval:v0` (9 files, 4 MB): the four eval episode JSONLs with raw text and the eval logs. Manifest `handoff/MANIFEST-eval.txt`.
* File names inside artifacts are repo-relative, so `wandb artifact get ... --root .` restores them in place; `scripts/publish_handoff.py --phase <training|eval> --verify .` checks size and sha256 against the manifest.
* Coordination: `STATUS_TRAINING` / `STATUS_EVAL` lines in CLAUDE.md flip from `PENDING` to `READY_FOR_TRANSFER`; the dev agent polled `git fetch` every 20 minutes.

### Consequences

* Good, because both phases verified on the Mac (`all 56 files verified OK`, `all 9 files verified OK`) and the model ran a smoke eval.
* Good, because the same mechanism can ship adapters to a new GPU provider.
* Bad, because tidying delivered files (moving the crashed-launch log) would break manifest verification, so delivered files stay where they arrived.
* Bad, because a 20-minute poll means up to ~20 minutes of latency and polls die with the session.

## Implementation Plan

* **Affected paths**: `src/wikigame/handoff.py` (`sha256_file`, `build_manifest`, `verify`, `default_files`, phases `training` and `eval`), `scripts/publish_handoff.py`, `handoff/MANIFEST-*.txt`.
* **Commands**: `uv run wandb artifact get aiwizards/wiki-game/wikigame-handoff-training:latest --root .` then `uv run python scripts/publish_handoff.py --phase training --verify .`.

### Verification

- [ ] `uv run python scripts/publish_handoff.py --phase training --verify .` prints `all 56 files verified OK`.
- [ ] `uv run python scripts/publish_handoff.py --phase eval --verify .` prints `all 9 files verified OK`.
